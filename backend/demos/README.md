# WebAgent Demo Scripts

This directory contains demo scripts that showcase the features and capabilities of the WebAgent platform.

## Available Demos

- **`multiagent_workflow_demo.py`**: Demonstrates the complete LangGraph multiagent workflow with agentic mode toggle, showing how multiple agents collaborate to solve complex research tasks.
- **`document_extraction_demo.py`**: Demonstrates the Document Extraction Agent's capability to extract structured information from documents.
- **`web_research_demo.py`**: Shows how the Web Research Agent searches the web and retrieves relevant information.
- **`internal_research_demo.py`**: Demonstrates retrieval of information from internal knowledge bases using vector embeddings.
- **`coding_assistant_demo.py`**: Showcases the Coding Assistant Agent's ability to generate code for various tasks.
- **`data_analysis_demo.py`**: Demonstrates data analysis and visualization capabilities on sample datasets.
- **`ft_demo.py`**: Demonstrates the fine-tuning service for customizing language models.

## Running the Demos

### Prerequisites

- Properly configured environment variables (check `.env.example` at the project root)
- Conda environment activated: `conda activate agents`
- Required dependencies installed: `pip install -r ../requirements.txt`

### Execution

Run any demo script using Python:

```bash
# To run the multiagent workflow demo
python -m backend.demos.multiagent_workflow_demo --query "Your query here" --agentic True

# To run a sample query with the multiagent workflow
python -m backend.demos.multiagent_workflow_demo --sample complex_research

# To run the document extraction demo
python -m backend.demos.document_extraction_demo

# To run the web research demo
python -m backend.demos.web_research_demo

# To run the internal research demo
python -m backend.demos.internal_research_demo

# To run the coding assistant demo
python -m backend.demos.coding_assistant_demo

# To run the data analysis demo
python -m backend.demos.data_analysis_demo

# To run the fine-tuning demo
python -m backend.demos.ft_demo
```

## Directory Structure

- `demo_docs/`: Contains sample documents generated by the demos
- `demo_data/`: Contains sample datasets generated by the data analysis demo
- `demo_outputs/`: Contains outputs generated by the demos (code files, visualizations, etc.)

## Creating New Demos

When creating new demo scripts, follow these guidelines:

1. Use proper Python docstrings to document the script's purpose
2. Include a clear usage section in the docstring
3. List all requirements and prerequisites
4. Implement proper error handling
5. Use the logging module for console output
6. Include sample data generation where appropriate
7. Document the expected output

## Note on Sample Data

The demo scripts generate sample data when needed. If you want to use your own data:

1. For document demos: Place your documents in the `demo_docs/` directory
2. For data analysis: Place your CSV files in the `demo_data/` directory

The scripts will use existing files if they're available, or generate sample data if needed.

## Fine-Tuning Service Demo

The `ft_demo.py` script demonstrates how to use the FineTuneService to fine-tune models and track experiments with MLflow.

### Prerequisites

Before running the demo, make sure you have:

1. Installed the required dependencies:
   ```bash
   pip install mlflow torch transformers
   ```

2. Set up MLflow (optional, will use a local SQLite database by default):
   ```bash
   # Set custom MLflow tracking URI if needed
   export MLFLOW_TRACKING_URI=sqlite:///mlflow.db
   
   # Start MLflow UI (optional, for viewing results)
   mlflow ui --port 5000
   ```

### Running the Demo

To run the fine-tuning demo:

```bash
# Basic usage
python -m backend.demos.ft_demo --model-id gpt2-small --dataset summarization --mode lora8

# Advanced usage with custom parameters
python -m backend.demos.ft_demo \
    --model-id gpt2-small \
    --dataset squad \
    --mode lora16 \
    --epochs 2 \
    --learning-rate 2e-5 \
    --batch-size 8 \
    --grad-accum 4 \
    --save-model \
    --run-name "gpt2-squad-lora16-demo"
```

### Command-Line Arguments

The demo script supports the following arguments:

| Argument | Description | Default |
|----------|-------------|---------|
| `--model-id` | ID of the model to fine-tune | gpt2-small |
| `--model-path` | Path to the model | models/{model_id} |
| `--dataset` | Dataset to use (squad or summarization) | summarization |
| `--mode` | Fine-tuning mode | lora8 |
| `--epochs` | Number of training epochs | 1 |
| `--learning-rate` | Learning rate for optimization | 1e-4 |
| `--batch-size` | Batch size for training | 4 |
| `--grad-accum` | Gradient accumulation steps | 2 |
| `--device` | Device to use (cpu, cuda, mps) | auto-detect |
| `--max-tokens` | Maximum number of tokens for generation | 100 |
| `--temperature` | Temperature for generation | 0.7 |
| `--save-model` | Save the fine-tuned model | False |
| `--save-name` | Name to save the fine-tuned model as | {model_id}_{mode}_{dataset} |
| `--run-name` | Name for the MLflow run | auto-generated |

### Viewing Results

After running the demo, you can view the results in the MLflow UI:

```bash
mlflow ui --port 5000
```

Then open your browser to http://localhost:5000 to see the experiment tracking information, including:
- Training parameters
- Loss and accuracy metrics
- Model artifacts
- Evaluation results
